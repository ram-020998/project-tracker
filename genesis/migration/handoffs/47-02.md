## gk README — the state-fact catalogue (`gk validate`), two-tier
A **state fact** is a value that changes per release and must live **only** in `knowledge/state/current.yaml`,
never restated in a pack / core / reference / procedure. `gk validate` scans those prose docs after stripping
code spans/fences **and** URLs, and never scans `state/`. Two prose-heuristic rounds failed in opposite
directions, so the check is now **two-tier** (review-3): a small exact/strict set **blocks**, everything looser is
a **warning** the reviewer reads each round.

**ERROR (blocks `gk validate`):**
- **Exact** — any literal **non-integer** scalar value from `state/current.yaml` (length ≥ 3) appearing anywhere
  outside `state/` (e.g. `v0.69.0` pasted into a pack). Exact match, so it cannot misfire on prose. Pure integers
  are **excluded** (a bare number collides with ports/line numbers/issue ids; test counts are covered by the strict
  runner form). Like every tier, the exact match runs **after** code spans/fences and URLs are stripped, so a
  literal state value inside `` `code` `` or a URL target is allowed (the §6.2 review is the backstop).
- **Strict forms** — a known repo + a **pin separator** (space, `@`, `==`, `-`, `/`, `:`) + optional `v` + semver
  (`genesis v0.77.0`, `genesis@v0.77.0`, `genesis==0.77.0`, `kiro-agent-sdk@0.77.0`, `genesis-workflows: v0.22.0`;
  repo names matched **longest-first** so `genesis-workflows v…` is reported as genesis-workflows and `genesis-core`
  alone never splits into `genesis`+`core`); `DB v<N>`; `db_current_version`; a CI pipeline/ci/job id with **≥ 6
  digits** (`#7087827`, `pipeline #?7087827`, `CI 7087827`, `job 7087827`); a test-runner word + a count
  (`pytest|vitest|jest|unittest N`, where `N` is not followed by a path or flag).

**WARNING (printed, never blocks):** bare semver (`0.69.0` / `v1.2.3`), `version <N>`, a migration id in prose
(`m0024`), a hyphenated CI id (`gl-9931`), a bare `<n> tests` count.

**ALLOWED (neither):** anything in `knowledge/state/`; an identifier inside a `` `code` `` span/fence; a version
inside a URL or markdown-link **target** (balanced-paren tokenizer; the link **text** is still scanned); short
counts after ambiguous words (`run 2`, `job 3`, `ci 3`, `pipeline 2`, `step 13`, `retry 3 times`, `port 8760`);
short `#ref`s (`#12`); `HTTP 409`; two-part numbers that are not semver (`section 3.2`, `Python 3.11`); a runner
with a path/flag (`pytest -q`, `pytest tests/x.py`, `go test ./...`).

Detection is **heuristic** by nature: the ERROR tier is the mechanical guarantee; the WARNING tier + the §6.2
human review are the backstop. (Full catalogue also lives as the docstring on `STATE_ERROR_PATTERNS` /
`STATE_WARN_PATTERNS` in `core.py`.)
