### Decisions / deviations

- **`extends` + a hidden job instead of a literal YAML anchor** (spec §1). Same effect (shared stage, image,
  before_script); `extends` is GitLab's documented way to merge job hashes. Reviewer agreed.
- **No `version-sync` job** (spec §1 allows folding): root `testpaths = ["tests"]`, so 50-07's
  `tests/test_version_sync.py` is collected by the `genesis` job's `pytest -q`. A comment in that job says so.
- **`scripts/install-packages.sh` not listed separately in `clean-install`'s `changes`**: `scripts/**/*` already
  matches it (inline comment).
- **`--python python`**: the script keeps a bare name as a PATH lookup; its default `<repo>/.venv/bin/python` does not
  exist on a runner and would stop the job.
- **§3 shallow clone**: GitLab evaluates `rules: changes` on the server: for a push it compares with the previous
  pushed commit, and it is always true for a new branch or tag
  ([GitLab docs, troubleshooting jobs](https://docs.gitlab.com/ci/jobs/job_troubleshooting.html)). The runner's
  depth-20 clone is not involved, no job uses `compare_to`, and there are no MR pipelines. A push touching `packages/`
  therefore matches `packages/**/*`; 50-08's first push is a new branch, so every job runs.
- **SDK lint rule set not widened** (e.g. `I` import order, as the parser has): §2 asks for a clean lint under the
  package's config; a wider rule set is a separate decision.
- Every Python job uses `image: python:3.13` (ADR-024); the parser's old job used `python:3.13-slim`, it now gets the
  full image like the others. No ADR deviation.

### Lesson candidates

- When a monorepo installs its libraries with one command and only the app's `[dev]` extra, each library's CI job
  depends on the root dev extra being a superset of the library's own; that holds by coincidence unless a test checks it
  (review Minor 1).
- `genesis status` reports `http://127.0.0.1:8760` while the server runs on another `--port` (seen here on 8791;
  pre-existing, review Nit 2). Backlog candidate for the launcher.
