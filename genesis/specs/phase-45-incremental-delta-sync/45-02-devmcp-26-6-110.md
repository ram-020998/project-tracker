# 45-02 — Adopt Dev MCP 26.6.110

> **Status:** 🟡 DRAFTED. Repos: **genesis**, **genesis-workflows**. Parent: `specs/phase-45-incremental-delta-sync.md`.
> Amends ADR-038 (managed-native Dev MCP).

## 1. Install

- Install the 26.6.110 bundle through the existing combined installer (`ConfigService.install_appian_dev_bundle` /
  Settings → MCP / `genesis mcp install-native appian-dev <bundle>`). It installs the MCP **and** the bundled SAIL CLI.
  Expected version `0.1.0+<sha8>` (installer suffixes the sha when the base version already exists).
- No installer change expected; verify `uv sync` + entry-point check pass under Python 3.13 (bundle requires ≥ 3.13).
- The fleet symlinks the host `~/.genesis/mcp-servers` and `~/.genesis/cli-tools`, so one host install upgrades every
  instance (restart needed).
- **Do not** run the bundle's `bin/install-skills.sh`: it writes into `~/.kiro`, which Genesis doesn't own (§7 lesson,
  never relocate/overwrite the user's Kiro home). The bundled `skills/appian` is noted for a future skill refresh.

## 2. Registry (genesis-workflows `mcp-registry.json`)

- Add **`listObjects`** to the `appian-dev` **read-only** `tool_allowlist` (72 → 73). Read-only, annotated
  `readOnlyHint=True`.
- Package tools are **not** added to any registry entry (umbrella Q1): they are only called by Genesis code
  through the 45-05 client, so no agent or chat can be granted them.
- `appian-dev-write` (Phase 42) is unchanged.

## 3. Version-mismatch detection

The 26.6.110 server refuses every call when the site plugin is a different build, with a message starting
`Refused: this MCP server and the DevMCP plugin on … come from different builds`.

- `genesis/kb/dev_mcp.py`: add `version_info(config) -> dict` (calls `getDevMcpVersionInfo`, exempt from the gate) and
  a pure `classify_tool_error(text) -> "version_mismatch" | "auth" | "unreachable" | "other"` (matches the `Refused:`
  prefix, HTTP 401 / `APNX-1-4187-*`, network errors).
- `ConfigService.dev_connection_check()` gains a `devmcp` block: `{plugin_version, plugin_sha, server_sha, match,
  recommendation}`.
- **Settings → MCP → Appian MCP servers panel** and **Settings → Environments → Test connection** show a clear banner
  on mismatch: "The Dev MCP plugin on <site> is <plugin_version>; Genesis's Dev MCP server is a different build —
  install the matching bundle from <site>/suite/plugins/servlet/stateless/dev-mcp-bundle."
- Sync runs (45-06) map a `version_mismatch` to a terminal error with the same text.

## 4. Tests

- `classify_tool_error` table test (mismatch / auth / unreachable / other).
- `dev_connection_check` with a stubbed `version_info` (match + mismatch).
- Registry guard: `listObjects` ∈ `appian-dev` allowlist; **no** package tool in any registry entry's allowlist.
- Web: the mismatch banner renders (+ jest-axe).

## 5. Acceptance

`getDevMcpVersionInfo` through Genesis reports matching shas; `listApplications` and `listObjects` work from both
fleet instances; no plugin/bundle recommendation shown.
