### Contract reconciliation (each fix named)

1. **Steer answer field — code fixed.** `POST /steer` answered `{ok, seq, status}` (53-07 As built); the table and
   the event say `message_seq`. `ChatSession.steer` now returns `{ok, message_seq, status: "queued"}`. No web caller
   yet (53-10), so nothing else moved.
2. **Steer not queued — code fixed.** An engine answer without `queued: true` was reported `queued` and stored. Now it
   raises `ChatNotRunningError` before anything is stored → 409, like an engine error.
3. **`/system/kiro` `installed` — code fixed (m3).** `check_kiro()` gains a `binary` key (the path `resolve_binary`
   found: PATH, then `~/.local/bin`); `kiro_auth._kiro()` reads it through `preflight.kiro_cli_status()` (the L-098
   import guard), so status, whoami, login and logout run the binary sessions launch. `shutil.which` is gone from
   `kiro_auth`.
4. **SSE row — table fixed.** Every event carries the stream's `seq`; `error {type, seq, detail, code}` with `code`
   null when unclassified, and the route's busy-race guard sends `error {type, detail}` with neither (pre-existing,
   left as is: it cannot be reached once `is_busy` has answered).
5. **Clear / Compact — table fixed.** `{ok, error}` with `error` null on success (was `error?`); 409 while a turn runs.
6. **Commands — table fixed.** `{commands: [{name, description, meta?}]}`; Genesis's `/clear` and `/compact` carry no
   `meta`.
7. **GET session — table fixed.** A typed `/clear` / `/compact` reply has `meta {command, ok}` (53-07); `session` has
   no `kiro_session_id`.
8. **Cancel, preflight, skills, skills/update, runs — table made exact** (full shapes, 404s); the code already matched.

### Decisions / deviations

No ADR deviation.

1. **"From the running backend"** = the real FastAPI app in-process (`create_app` + `TestClient`) with the real SDK
   client over the SDK's replaying fake engine, the way Phase 51 recorded its fixtures; not the fleet (D20, no
   restart) and not live kiro-cli (credits; the recordings are kiro-cli 2.37.1's own frames).
2. **The steer code followed the table** (`message_seq`), not 53-07's `seq`: one name for one value on the answer and
   on the event.
3. **`check_kiro()` gains `binary`** (53-08 m3's "better" option) rather than a second PATH-then-`~/.local/bin` copy in
   `kiro_auth` (L-109). Additive on a public SDK function.
4. **No web type or web contract test here:** `web/src/types/chat.ts` lacks the new fields (53-10 W8); a
   `contract.test.ts` against these fixtures belongs with those types.
5. **`session.status` and the `queued: false` case use `FakeV3Client`:** no recording has a summarization inside a
   prompt or a refused steer.

### Lesson candidates

- **A global git setting reaches every test that shells out to git:** `commit.gpgsign true` made three testexec
  tests fail with exit 128 (and a plain `git commit` hang in an agent shell). Tests that run `git commit` should pass
  `-c commit.gpgsign=false` (or set `GIT_CONFIG_GLOBAL` to an empty file) the way they already pass `user.name`.
- **Starlette's TestClient returns a streaming body only when the stream ends:** to act during a turn (steer, Stop),
  act from another thread on a signal the engine side gives (here the fake engine's log of `session/prompt`), not on
  an SSE event.
