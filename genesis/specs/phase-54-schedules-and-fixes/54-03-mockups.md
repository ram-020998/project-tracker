## 2. Surfaces and the starting layout for each

1. **Schedules page** (`/schedules`): header with **New schedule**; filter chips All · System · Mine · Paused ·
   Failing; one table: name, target (icon + workflow / agent / regression app), frequency in words with zone, next run
   (relative + exact on hover), last result (status pill + relative time), on/off switch, row menu (Run now, Pause,
   Duplicate, Delete or Reset to default). States: empty "Mine", a Paused (failing) row, a row waiting at a gate.
2. **New / edit schedule** (dialog or full page; show both and let the user choose): step 1 target (Run a workflow ·
   Agent prompt · Regression suite); step 2a workflow picker (only `schedulable`) + the launch form; step 2b agent
   prompt: custom agent picker (optional), prompt textarea, skills multi-select, read-only server multi-select (custom
   servers with a "this server only reads" checkbox), model; step 2c application picker; step 3 frequency (the five
   D9 forms, zone, next 5 runs preview) and **Advanced** (grace, max run duration, gate max wait, failures before
   pause, end date, max runs); step 4 name + review.
3. **Schedule detail**: StatusHeader (state, next run, last result, Run now, Pause/Resume, Edit); a settings card
   (target summary, frequency, advanced policy; for `application-sync` all of today's `ApplicationSyncSection` fields,
   D15); a history table (slot, outcome incl. `missed`/`skipped` with reason, run link, duration, credits with
   provenance, total row).
4. **Catalog → Agents tab** (`/catalog/agents`): cards or table of custom agents (name, description, skills, servers,
   model, "used by N schedules"); **New agent** editor (name, description, instructions, skills, read-only servers,
   model); **Run** dialog (prompt → starts once, link to the run); delete refused while in use (message lists the
   schedules).
5. **Notification bell**: unread badge; popover list (icon by kind: needs you, failed, auto-paused, missed), relative
   time, link, mark read, mark all read; empty state.
6. **Chat**: new-session control with an optional custom agent picker (read-only mode only); the chat header showing
   the agent; a note that in chat the agent has read-only tools (D5).
7. **Story page — Design tab:** StatusHeader (design stage status, run status + link + time, "Edit / chat" and
   "Re-run design" as real buttons); main column: the design document in a SectionCard (theme-aware frame, open in new
   tab); sidebar: details (generated by run, updated at, lane), and the run/empty/failed states as SectionCards with
   EmptyState, not the dashed `EmptyPanel`.
8. **Story page — Implementation tab:** StatusHeader (implementation stage, run, code-review lane state); stat tiles
   (objects created / updated / deprecated; ok / healed / error); an **Objects changed** table from
   `report.objects[]` (name, type with icon, action pill, new version, status); report and rollback document as
   SectionCards (tabs inside one card, or stacked; show both); sidebar details.
9. **Story page — Verification:** its own tab (instead of under every tab), same card pattern; show the gate state, the
   totals and the proposals.
10. **Feature page — Overview tab:** a summary row (stage progress with labels, stories / epics / tests counts, last
    activity); a **Needs attention** list across all stages (unanswered questions, spec changed, open CR, failed or
    gated stage run, stories not on a board); stage cards with prerequisite shown as "Needs Spec finalized" rather than
    a dimmed card; no "arriving in later phases" or "status derived from stages" text. Shared tabs component for the
    page (not the hand-rolled tablist, `FeaturePage.tsx:94-106`).
11. **Feature page — Activity tab:** the Timeline: grouped by day, newest first, a stage filter, typed icons
    (lifecycle, run, change request, finalization), relative times, links; "Load more".

### Decisions / deviations

No ADR deviation.
1. **Theme button sets the app theme** (`useTheme().setTheme`, persisted), not a wrapper class as older mockups do, so
   the portalled dialogs, popover and menu follow it.
2. **jest-axe per frame, then the section with `landmark-unique` off** (accepted by review).
3. **Compact `StatGrid`** (local to `story.tsx`) for the Implementation counts and the Verification totals, not the
   shared `MetricCard`: its display numerals are too large for six or eight counts (seen in the screenshots). 54-09
   should promote it or give `MetricCard` a compact size, not add a third grid.
4. **Row menu over `@radix-ui/react-dropdown-menu` directly** (an existing dependency, used by `select.tsx`). 54-07
   should add a shared menu primitive in `shared/ui`.
5. **Application-sync options read-only with Edit** on the detail page (Edit opens the frequency step + options), not
   inline inputs as today's Settings card. Alternative: inline editing on the detail page. *Question for the user.*
6. **On/off switch = "does it fire"** (off for Off, Paused and Paused (failing)); turning it on resumes and clears the
   failure count. F1 keeps `enabled` and `pause_reason` apart, so the user must say which field the switch writes
   (review m4). *Question for the user.*
7. **Copilot is shown disabled** in a custom-agent chat ("Not available in a chat with a custom agent"); D6 says only
   the read-only assistant takes an agent but not what happens to the Copilot toggle in that session. Alternative:
   hide the toggle. *Question for the user.*
8. **The wizard's agent-prompt step** shows the picked custom agent's skills and servers in a summary line, but the
   skill and server pickers show only the schedule's own picks. Alternative: show the agent's picks as locked, ticked
   rows. *Question for the user.*
9. **Section 9 Verification** credits shown as "n/a" (unavailable) to show that provenance; a real verification run
   is metered.
10. Native `type="time"` inputs show 12-hour AM/PM in an en-US browser locale beside 24-hour words and previews
    (review n4); the real form behaves the same. *Mentioned to the user.*

### Found, not fixed (out of scope; for follow-up)

- **Opacity modifiers on token colours generate no CSS.** `tailwind.config.ts` maps colours to bare `var(--…)` (no
  `<alpha-value>`), so `bg-primary/10`, `border-warning/40`, `bg-warning/10`, `bg-surface-1/70`, `ring-primary/40` and
  similar produce no rule at all: 0 matches in the built CSS. 8 source files use `bg-primary/10` (for example
  `VerificationSection.tsx` gate panel, `TopBar.tsx` header, the run-inspection mockup). The new code avoids them
  (`grad-brand-soft`, `*-subtle`). Backlog item for the docs agent.

### Lesson candidates

1. **An opacity modifier on a `var()` colour is a silent no-op in this Tailwind setup.** Classes such as
   `bg-primary/10` pass lint, typecheck and jsdom tests and render nothing; only a grep of the built CSS shows it. Use
   the `*-subtle` tokens or `grad-brand-soft`, or define the colours with `<alpha-value>`.
2. **A mockup page that shows two options of one surface side by side needs jest-axe per option frame**: equal region
   names across the options trip `landmark-unique` though neither option alone has a defect. Run axe per frame with all
   rules and on the page with only that rule off.
3. **A mockup's dates must be relative to page load, including previews** (review n2, n6): fixed dates turn into "next
   runs" in the past by the time the user reviews.
