# 47-01 — Inventory, area taxonomy, schemas, batch plan

> **Status:** 🟡 DRAFTED 2026-10-19. Umbrella: `../phase-47-knowledge-system.md`. Agent: `kiro_default` (the
> migration agents do not exist yet). Review: `genesis-migration-reviewer`. **Gate:** the user approves the areas
> and the batch plan.

## Context manifest — read only this
- The umbrella spec (all of it — it is the design).
- `bible/03-codebase-map.md` (to derive the areas) and the directory trees of the five code repos (`glob`, not
  file contents).
- File sizes and line counts of every source (by script — do **not** read the corpus).

## Goal
Fix the ground the whole migration stands on: what the sources are, how the knowledge is partitioned, what every
artifact looks like, and how the reading is split into sessions that fit the budget.

## Work
1. **Base tag.** Tag project-tracker HEAD `knowledge-migration-base` and push the tag. Every later pass cites
   sources at this tag.
2. **Inventory** → `migration/inventory.csv` (generated by `migration/scripts/inventory.py`, folded into `gk` in
   47-02): every file under `genesis/` with path, bytes, chars, lines, type, **class** (`extract` /
   `archive-only`) and a reason for every `archive-only` (e.g. binary image with no text). JSON fixtures and
   contract files are `extract`.
3. **Area taxonomy** → `migration/areas.yaml`: per area `id`, `name`, one-paragraph `scope`, `code` path globs
   over the five repos, and `topics` (words that identify it in the docs). Derive it from the code and
   `bible/03`; start from the umbrella's candidate list (§3.5) and change it where the code says otherwise.
   Two pseudo-areas exist: `all` (rules that apply everywhere → `CORE.md`) and `history` (no pack).
   Coverage rule: every tracked source file in the code repos matches ≥ 1 area glob — list the exceptions
   (generated or vendored files) with reasons.
4. **Schemas** → `migration/schemas/`: `knowledge-unit.schema.json` (umbrella §3.2, plus `fate`, `fate_target`,
   `primary_area`), `coverage.schema.json` (line range → unit ids or a skip reason: `blank`, `heading-only`,
   `formatting`, `duplicate:<KU>`), `rule.frontmatter.schema.json` (umbrella §4), `context-manifest.schema.json`,
   `question.schema.json` (`id`, `units`, `question`, `answer_points`, `high_stakes`). Each schema ships with one
   valid **real** example taken from the corpus (an ADR from `decision-log.md`, a lesson from `bible/06`, a
   contract field from the Hub contract) and one invalid example.
5. **Templates** → `migration/templates/`: the handoff note (what was done, counts, check outputs, open points,
   what the reviewer should look at), the review request, the conflict entry.
6. **Batch plan** → `migration/batches.yaml`: batches `P1`, `P2` (the pilot, 47-03) and `B01…Bnn` (47-04).
   Each batch lists sources as whole files or contiguous line ranges split at headings; **≤ 250K chars** per
   batch; every `extract` file covered **exactly once** (no gap, no overlap). Keep related documents together
   (a phase's spec + sub-specs + progress doc in one batch where the budget allows) so duplicates meet inside
   one batch.
7. **Progress** → `migration/PROGRESS.md`: a ledger table with one row per unit of work (47-01 … 47-11, every
   batch and every per-area session), status, commit, review verdict; and a §Method changes log.

## Outputs
`migration/{inventory.csv, areas.yaml, batches.yaml, PROGRESS.md, schemas/, templates/, scripts/inventory.py}`,
the tag, and `migration/handoffs/47-01.md`.

## Definition of Done
- Inventory rows = `git ls-files genesis/ | wc -l` at the base tag; every `archive-only` has a reason.
- Every code-repo file maps to an area or is listed as an exception with a reason.
- Every schema validates its valid example and rejects its invalid one (`python3 -m json.tool` + a small
  validation script; `jsonschema` is not required — the script may hand-check required keys and enums).
- The batch plan passes a script check: union of batch ranges = all `extract` lines, no overlaps, every batch
  ≤ 250K chars.
- The user approved `areas.yaml` and `batches.yaml` (recorded in the handoff with the date).

## Verification (reviewer — on top of umbrella §6)
- Re-count the inventory and the batch coverage independently.
- Check 20 random code files across the repos against the area globs.
- Check that the unit schema can express every type in §3.2 by mapping 10 random paragraphs from different
  sources (bible/04, bible/06, decision-log, a progress doc, a contract doc) onto it.
- Check the batch boundaries do not split a paragraph, table or code block.
