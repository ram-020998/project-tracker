# 48-02 — API: read the Object Wiki

> **Status:** ✅ DONE 2026-10-21 (genesis `940deef` + `148c064`, local; review SHIP — see As built). Repo: **genesis** (backend). Parent: `specs/phase-48-object-wiki-ui.md`.
> Decisions: 48-01 D4, D6, D7. Read-only; no migration; no collab/Hub change.

## 1. Goal

Two read-only endpoints that give the web everything the Object Wiki tab (table) and object page (history) need, in
one request each, from the **local** tables (ADR-070 — teammates' entries are already pulled into them).

## 2. Endpoints (under `/api`, ADR-028)

New module `genesis/genesis/api/object_wiki.py` → `register_object_wiki_routes(api, settings, kb_store)`, built and
registered in `genesis/genesis/api/app.py` like the other `register_*_routes` (stores built from `settings.db_path`,
closed over by the route functions — `genesis/api/workbench.py:55-63`). Plain `def` handlers (FastAPI threadpool),
GET only.

| Method + path | Response | Errors |
|---|---|---|
| `GET /applications/{app_uuid}/wiki` | `{ "app_uuid", "app_name", "objects": [WikiObjectRow] }` — every page of the app, sorted by `last_changed_at` desc, then name | 404 `Application '<uuid>' not tracked` |
| `GET /applications/{app_uuid}/wiki/{object_uuid}` | `{ "app_uuid", "app_name", "object": WikiObjectRow, "entries": [WikiEntry] }` — entries **newest first** | 404 app not tracked; 404 `No wiki page for object '<uuid>'` |

An app with no pages returns `objects: []` (not 404).

### 2.1 `WikiObjectRow` (identical in list and detail — L-039: one builder)

| Field | Source |
|---|---|
| `object_uuid` | page |
| `name` | current KB row `kb_objects.name` → else `wiki_object_pages.object_name` → else `object_uuid` (D4) |
| `type_key` | `normalize_object_type(kb type → else page object_type)` (§4) |
| `type_raw` | the un-normalized value used above (may be null) |
| `in_kb` | bool — a current KB row exists |
| `summary` | `current_summary` (nullable) |
| `entry_count` | count of the page's entries (0 allowed) |
| `first_documented_at` | earliest entry `created_at` (else page `created_at`) |
| `last_changed_at` | latest entry `created_at` (else page `updated_at`) |
| `latest_change_kind` | latest entry `change_kind` or null |
| `latest_author` | latest entry `author_username` or null |
| `latest_object_version` | latest entry `object_version` or null |
| `is_deprecated` | `latest_change_kind == "deprecated"` |

"Latest entry" = the page's entry with the greatest `(created_at, id)`. **Never use `latest_entry_id`** — it is
local-only and is null on pulled pages (48-01 §2.8).

### 2.2 `WikiEntry`

`id`, `change_kind`, `business_description`, `technical_description`, `is_bugfix` (**bool**, not 0/1),
`change_reason`, `object_version`, `author_username`, `created_at`, `story_key`, `story` (§5: `{id, key, title}` or
null). Collab provenance columns are not exposed.

## 3. Store (`genesis/genesis/kb/object_wiki.py`)

Add read methods to `ObjectWikiStore` (existing methods unchanged; no writes; never creates tables):

- `list_objects(app_uuid) -> list[dict]` — **one** SQL query: pages `LEFT JOIN` the current `kb_objects` row
  (`app_uuid`, `object_uuid`, `valid_to_sync IS NULL`; at most one row per object — guard against duplicates, L-032)
  plus per-page entry aggregates (count, min/max `created_at`, latest entry fields via a correlated subquery ordered
  `created_at DESC, id DESC`). No N+1.
- `get_object(app_uuid, object_uuid) -> dict | None` — the same row shape for one page + its entries ordered
  `created_at DESC, id DESC`, with story resolution (§5); `None` when there is no page.

The DTO mapping (§2.1/§2.2, `bool(is_bugfix)`, name/type precedence) lives in **one** pure helper used by both, so list
and detail can't drift (L-039).

## 4. Type normalization (`genesis/genesis/kb/object_types.py`, new, pure)

`normalize_object_type(raw: str | None) -> str` — lower-case, drop non-alphanumerics, look up an alias table; unknown
or empty → `"other"`. Canonical keys: `record_type`, `interface`, `expression_rule`, `process_model`, `constant`,
`integration`, `connected_system`, `web_api`, `data_type`, `site`, `group`, `translation_set`, `document`, `folder`,
`decision`, `report`, `other`. Aliases must cover the parser display names (`Record Type`, `Expression Rule`, …;
48-01 §2.8) and the real wiki variants (`record_type`, `recordData`, `constant`, …; 48-01 §2.4) — `recordData`/
`recordtype`/`record` → `record_type`, `rule`/`expressionrule` → `expression_rule`, `cdt`/`datatype` → `data_type`,
`processmodel`/`pm` → `process_model`. The web owns labels + icons (48-03).

## 5. Story resolution (D6, ADR-071)

For each entry: the local story whose `kb_stories.sync_uuid = entry.story_sync_uuid`, else whose
`kb_stories.key = entry.story_key`; **both scoped to the app** (`kb_stories.feature_id → kb_features.app_uuid =
app_uuid`). Result `story = {id: kb_stories.id, key, title}`; no match → `null` (the web shows the raw `story_key`).
Resolve in the same query or one batched query per request — not one query per entry.

## 6. Tests (pytest, `genesis/tests/`)

- `tests/test_object_types.py` — table-driven: every parser display name, every real wiki variant above, case/space/
  underscore variants, `None`/`""`/unknown → `other`.
- `tests/test_object_wiki_api.py` — fixture modelled on `tests/test_applications_api.py:53-71` (migrated temp DB,
  `KbStore` seed, `TestClient(create_app(...))`), seeding via `ObjectWikiStore.upsert_page`/`append_entry`:
  1. untracked app → 404 on both endpoints; unknown object → 404; tracked app with no pages → `objects: []`.
  2. list row fields equal the detail `object` fields for the same page (L-039).
  3. KB name/type win over the page's (renamed object); object not in KB → page values + `in_kb: false`.
  4. a **pulled-shape** page (`latest_entry_id` NULL, entries inserted directly with Hub-style `created_at`, e.g. a
     `Z`-suffixed value) still reports the right latest change / count (48-01 §2.8, L-084).
  5. entries newest first; `is_bugfix` is a JSON bool; `deprecated` latest → `is_deprecated: true`; a page with 0
     entries is listed with `entry_count: 0` and null latest fields.
  6. story resolution by `sync_uuid`, by `key`, a key from **another app** → null, no match → null.
  Fixtures use real value shapes (`GNS_000123`, real type strings — L-083).

This section is m4. **m1 is carried to 48-04:** during live acceptance, check that a pulled entry's `created_at` parses: `SELECT created_at, julianday(created_at) FROM wiki_object_entries WHERE published_by IS NOT NULL LIMIT 5` must not return NULL.

### Decisions / deviations (spec refinements; no ADR deviation)

1. **Ordering uses the parsed timestamp, not a string sort.** Entries are ordered `julianday(created_at) IS NULL, julianday(created_at) DESC, id DESC`. The spec said `created_at DESC, id DESC`. The reason is that `created_at` is a shared column (it crosses the Hub, L-084), so mixed forms (`Z`, `+00:00`, `+05:30`, no fraction) must compare correctly. A test uses a `+05:30` value that a string sort places wrong. Unparseable values sort last in both directions. The same rule applies to the list order (`last_changed_at` desc, then name NOCASE, then uuid) and to first/latest entry selection.
2. **Display values come from one SQL expression.** `name`, `first_documented_at` and `last_changed_at` are computed once in SQL, and the list ORDER BY uses the same expressions. A blank `created_at` (`""`, the Hub's null text) falls back to the page's `created_at` / `updated_at`.
3. **Story resolution (refines D6).** A `sync_uuid` match wins. Otherwise a `key` match counts only if exactly one of the app's stories has that key: an ambiguous legacy key such as `story-1-1` → `null` rather than a link that may be wrong. A blank key or sync id never matches. Everything is scoped to the app through `kb_features.app_uuid`.
4. **Types.** Parser types outside the spec's fixed canonical list (Control Panel, Translation String, AI Skill, Data Store, Application, Unknown) → `type_key: "other"`, and `type_raw` keeps the original value. **48-03:** for `other`, show `type_raw` as the label if you want something more specific than "Other". Extra aliases beyond the spec: `rulesFolder`/`knowledgeCenter`/`communityKnowledgeCenter` → `folder`, `outboundIntegration` → `integration`, `sailInterface` → `interface`, `tempoReport`/`processReport` → `report`, `customDataType` → `data_type`, and plurals of the main types.
5. **`is_bugfix`** is a JSON bool, and text values are handled (`""`/`"0"`/`"false"` → false).

### Lesson candidates

- **Sort timestamps that cross the Hub by their parsed value, not their string.** Strings authored locally and strings returned by the Hub can differ in form and offset (L-084). In SQLite, `julianday()` parses `Z`, `±HH:MM` and fractional seconds; unparseable values should sort last, and `id` breaks ties.
- **A list endpoint's ORDER BY and the derived field it returns should come from one expression.** Otherwise edge values (such as `""` → fallback) make the order and the displayed value disagree. This is a refinement of L-039 (review m2).
