## 1. Executive summary
The Genesis SPA is a **well-architected, token-driven React + Vite + Tailwind app** with a shadcn/Radix-style primitive set — **not** a messy codebase. Its "outdated" feel is **not** structural; it is **aesthetic + IA**: a **dark-by-default** palette, **flat low-elevation** surfaces, a **tight type scale**, restrained color/accent use, minimal motion, and a **thin, flat navigation** (single collapsed icon-rail, no breadcrumbs/top-bar/global-search) that has not kept pace with 16+ accreted surfaces. **This is exactly the profile a light-first, MUI-inspired evolution fixes with low risk** — the theming is already a pure token swap and only one file hardcodes color. The revamp is therefore **high-leverage presentation/IA work on a healthy foundation**, not a rewrite.

## 3. UX heuristic audit (cross-cutting, prioritized)
1. **Navigation & wayfinding (highest impact).** Sidebar defaults collapsed (icons-only) → weak discoverability + no labels for new users; **no breadcrumbs** for deep routes (`app › feature › spec`, `runs › run › node`); **no global search / command palette**; Catalog + Overview live *only* inside Settings (buried). → 27-02 to define IA: expanded-by-default or hybrid nav, breadcrumb bar, command palette, and reconsider Catalog/Overview placement.
2. **Visual hierarchy & density.** Flat `shadow-e1` surfaces + tight type scale + heavy tab strips (6 on App-detail, 7 on Settings) make dense pages read as uniform gray fields. → modern elevation + a stronger type scale + tab overflow/grouping (27-03/04).
3. **Consistency.** Strong overall (one primitive set, `Page` wrapper, shared states), but action bars vary (Spec = 7 inline controls, Run-detail header dense) and React-Flow is themed by **global CSS overrides** in `index.css` rather than tokens (3 surfaces: business-map, run-graph, memory). → tokenize React-Flow theming; standardize action bars/toolbars.
4. **Feedback & motion.** Minimal transitions (`duration-fast/base`); good `aria-busy` skeletons + toasts exist. → add tasteful, reduced-motion-safe motion (hover/elevation/enter) per the new language.
5. **Empty/loading/error.** Well-covered by `feedback/states` — keep the API, restyle.

## 4. Accessibility baseline
- **jest-axe coverage: 15 suites** assert `toHaveNoViolations` (applications, catalog/skills, chat, copilot, skills-chat, features, observability, library, memory, run-detail/documents, settings, copilot-settings, kiro, system, design-system). **Gaps (no axe test):** **Runs list**, **Run-detail (Flow)**, **Catalog main**, **Workflow-detail**, **Launch-form**, **Overview**, **Application-detail sub-tabs**. → 27-11 closes coverage to *every* page.
- **Focus/keyboard:** primitives use `focus-visible:ring-focus` + Radix (good). Verify custom canvases (React-Flow, d3 constellation) + the SplitPane drag have keyboard paths.
- **Contrast (token pairs, to verify with a tool in 27-03):** `--fg`/`--bg` excellent in both themes (~15:1+). **`--fg-subtle` on `--bg` is ~3–4:1 in *both* themes → below the 4.5:1 AA floor for small text** (used widely for meta/labels) → **refine `fg-subtle` in the new palette** (or reserve it for large/non-text UI). `--primary` as text/`--primary-fg` on primary ~4.5:1 (borderline) → nudge for comfortable AA.
- **Reduced motion:** the spinner already respects it; the new motion layer must too.

## 5. Design-system inventory
- **Primitives (`shared/ui`, 20+):** `button` (cva: primary/secondary/outline/ghost/danger × sm/md/lg/icon), `card` (+Header/Title/Body/Footer, `shadow-e1`), `tabs` (Radix underline), `dialog`, `tooltip`, `switch`, `input`, `badge`/`chip`, `segmented`, `skeleton`, `metric-card`, `health-dot`/status dots, `trend-chart`, `toast`, `file-drop`, `format` (RelativeTime/Duration/CreditBadge), `logo`. Radix + cva + `cn()` — a clean shadcn-style base to **evolve**, not replace.
- **Tokens (`styles/tokens.css`):** `:root/.theme-dark` (default) **+ a full `.theme-light`** — surfaces (bg/surface-1..3), text (fg/muted/subtle), primary/accent, semantic (success/warning/danger/info + `-subtle`), border/border-strong, focus, `color-scheme`. Radii sm/md/lg/xl, shadows `e1..e3`, motion `fast/base/slow` + `standard` easing, Inter + JetBrains-Mono. Tailwind maps every color → `var(--*)`.
- **Hardcoded-hex offenders (only 4 files):** `memory/MemoryGraph.tsx` (7 — constellation), `memory/graph.ts` (5 — `KIND_STYLE` palette), `memory/graph.test.ts` (2), `shared/ui/logo.tsx` (3 — brand gradient, acceptable). → memory graph is the sole reconciliation target (27-09); logo gradient may stay as an intentional brand token.
- **Inline styles:** near-zero outside `MemoryGraph` (12, expected) — token discipline is strong.

## 6. MUI reference study + adopt-vs-evolve
**What to borrow from MUI / Material Design 3** (as a *language*, not a dependency): a confident **type scale** (display/title/body/label + tabular numerics), **elevation** as meaningful hierarchy (tonal surfaces + soft shadows, esp. on light), **rounded geometry**, **purposeful motion** (state/enter transitions, easing), **dense-but-airy data surfaces** (tables/lists/graphs), clear **primary/secondary/tonal button** semantics, **filled/outlined inputs** with strong focus, and **accessible-by-default** patterns.
- **Adopt `@mui/material`:** + best OOTB Material-3 + a11y; − large migration off Tailwind/token/shadcn, heavier bundle, diverges from the proven gate discipline, re-tooling of every primitive. **Rejected.**
- **Evolve the existing token/Tailwind primitives to a MUI-inspired language:** + keeps the token swap + jest-axe + build gates + `/dev` gallery, lowest regression risk, no framework churn (ADR-027 respected); − bespoke design work. **Chosen** (confirmed with the user 2026-08-21).

## 7. Decisions (→ ADR-055 Accepted)
Confirmed with the user (2026-08-21):
1. **Light-first**, dark retained as a first-class, persisted, toggleable theme (toggle already exists in Settings→General→AppearanceSection; 27-04 flips the default + refines the palette).
2. **Evolve** the existing Tailwind/token/shadcn-style primitives to a **MUI-inspired** modern language — **do NOT** adopt `@mui/material`.
3. **Mockup medium = coded mockups in `/dev`** (real, themeable, double as the 27-04 foundation).
4. **Navigation intent (to design in 27-02):** expanded/hybrid nav with labels, a breadcrumb bar for deep routes, a command palette / global search, and a re-evaluation of Catalog/Overview placement.
5. **Scope guard:** presentation + IA only; **no** behavioural/API/DB change; discovered functional gaps → `specs/backlog/`.
