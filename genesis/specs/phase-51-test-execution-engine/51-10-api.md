## 1. Module + registration

New `genesis/genesis/api/testing.py` (`register_testing_routes`), plus additions in `api/workbench.py` and
`api/config_routes.py`. All under `/api` (ADR-028). Specific routes registered before any generic path-param route that
also matches them, proven by behaviour (L-096). Blocking work via `asyncio.to_thread` (L-026). Errors: 404 unknown
app/item; 409 `{"detail": …, "problems": [...]}` for readiness/lifecycle/contract refusals; 422 `{"detail": …,
"typecheck": [{file, line, col, message}]}` for a failed typecheck. The `api/testing.py` routes (51-05..51-08) answer
400 `{detail}` for an invalid request (a bad value, another application's record, a bad schedule). Secrets are write-only: no route returns a password.

**Setup jobs (D23).** Create workspace, Update testing runtime and Install Chromium run as background jobs, changing
the three synchronous 51-05 routes. A small in-memory `TestingJobs` registry in the app process (`genesis/genesis/testexec/jobs.py`)
holds `job = {job_id, kind (workspace-create · workspace-update-runtime · chromium-install), app_uuid (null for
Chromium), status running·succeeded·failed, started_at, finished_at, error, result}` (`result` = what the 51-05 route
returned). Single flight: one Chromium install per machine and one workspace job per app; a second POST returns 202 with
the running job. The work runs off the event loop (L-026) with its children recorded through `procs` in
`~/.genesis/testing/jobs/.pids`, reaped at startup (51-05 As built 7). Jobs are not persisted: after a restart the job
id is unknown (404), and the Setup view falls back to the setup/runtime reads, which report the real state. Finished
jobs are kept for 1 hour. A job's error text never contains a secret.

**Library replay (from 51-07 As built 3; backlog item 12 is in scope here).** `TestLibraryService.replay` runs
Playwright in the app process for tens of seconds and writes no `TE-` row. Expose it only as a `library-replay` job in
the same registry: single flight per item (a repeat POST returns the running job), a cancel that reaps the replay's
`.pids`, and F11-style retention of `<artifacts>/library-replays/` (keep the newest 20 per app; prune at startup and
after each replay). The startup `reap_stale_replays` stays.

### Lesson candidates

- **A background job must finish even when storing its outcome fails.** Put the store in the job's own `try` and set
  "done" in a `finally`. Otherwise one bad scrub wedges the single-flight key until a restart (51-10 review m1).
- **"Cancel" must also cover the child started just after it.** One reap can land between the worker's last check and
  its spawn. Keep reaping the job's own pid folder until its thread returns (51-10 review m4).
- **A route-table shadowing check is cheap and complete.** For every route, build a concrete URL from its template and
  assert that no earlier route matches it in full (unwrap FastAPI 0.139's `_IncludedRouter`). It proves L-096 for
  every route at once, beside one behaviour check per literal/parameter pair.
- **A "status filter" a service silently ignores is a silent no-op.** Discard returned 200 for an `analysing` capture
  while doing nothing. Refuse in the service under its lock, not only in the route (51-10 review m3).
