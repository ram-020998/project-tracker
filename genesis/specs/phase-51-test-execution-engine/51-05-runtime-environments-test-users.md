# 51-05 — Runtime, workspaces, environment types and test users

> **Status:** SPEC-DRAFTED 2026-11-02. Repos: **genesis** (backend), **playwright-appian** (only for gaps 51-03 lists).
> Parent: `specs/phase-51-test-execution-engine.md`. Decisions: 51-01 D1, D3, D4, D5, D8; F3, F4, F5, F8, F12.

## 1. Goal

Everything a test needs before the first script exists: the Node/Chromium runtime, the vendored `playwright-appian`,
one git workspace per application, the `apwt` integration client with safe subprocess handling, the environment type
with a single QA environment, the application's test settings and test users.

## 2. Runtime

- **Vendored package** (D4): `genesis/genesis/testexec/vendor/playwright-appian-<version>.tgz`, shipped as **package
  data** so an installed Genesis finds it (L-048); a `VENDORED_APWT_VERSION` constant beside it; the tarball's sha256
  recorded and checked before use.
- **Detection** (`genesis/genesis/testexec/runtime.py`): `node --version` (≥ 20), `npm --version`, the Chromium
  revision installed under `~/.genesis/testing/browsers` (`PLAYWRIGHT_BROWSERS_PATH`, F4), `git --version`. Exposed
  to preflight (`genesis/genesis/runtime/preflight.py`, warning not failure: Genesis runs without testing) and to the
  Settings → CLI card (51-11).
- **Chromium install**: an explicit action runs `npx playwright install chromium` from any workspace (or a runtime
  scratch project) with `PLAYWRIGHT_BROWSERS_PATH` set; never at startup, never silently (D4).
- No Node download, no auto-update (ADR-038/040 rule).

## 3. `TestWorkspace` (`genesis/genesis/testexec/workspace.py`)

Per application at `~/.genesis/testing/apps/<app_uuid>/` (F4), created on first use:
- `git init`; files from templates kept in `genesis/genesis/testexec/templates/`: `package.json` (exact versions:
  `playwright-appian` as `file:` to a copy of the vendored tarball inside the workspace `vendor/` — so the workspace is
  self-contained and portable, D4; `@playwright/test` 1.59.1; `typescript` pinned for typecheck), `package-lock.json`
  produced by the first install, `playwright.config.ts` (generated by 51-06), `tsconfig.json`, `.gitignore`
  (`node_modules/`, `test-results/`, `playwright-report/`, `.auth/`, `.env*`), `lib/` (51-07 §2), empty `actions/`,
  `setups/`, `cases/`, `suites/`, `captures/` (F5), a `README.md` saying the folder is managed by Genesis.
- `npm ci` (first time `npm install` to produce the lockfile) with a timeout; failures surface with npm's message.
- Write API used by 51-07: `write(path, text) → typecheck → commit(message)`; `typecheck()` = `npx tsc --noEmit`;
  `head()`, `log(path)`, `show(commit, path)`, `revert_file(path, commit)`, `export(commit, dest)` (`git archive` into a
  run folder; `node_modules` symlinked when the commit's lockfile equals the workspace's, else `npm ci` there — 51-06);
  `status()` for outside edits (hash vs catalog, D16.7). All git calls use argv lists and a fixed author
  ("Genesis <genesis@localhost>" + the canonical username in the message trailer).
- Upgrade: when `VENDORED_APWT_VERSION` changes, the workspace offers "Update testing runtime" (rewrite the tarball +
  `npm install` + commit); never automatic.

## 4. `ApwtClient` (`genesis/genesis/integrations/apwt/`)

The program-side seam (like `SailClient`, `genesis/genesis/integrations/sail/client.py`): resolves the workspace's
`node_modules/.bin/apwt`; builds argv lists (no shell); always `--json`; parses results into typed objects and maps
`apwt` error codes (`NOT_FOUND`, `HOST_NOT_ALLOWED`, `SESSION_GONE`, `VERSION_MISMATCH`, …) to typed exceptions.
- **Environment**: a minimal allow-listed env (`PATH`, `HOME`, `TMPDIR`, `PLAYWRIGHT_BROWSERS_PATH`,
  `PLAYWRIGHT_APPIAN_HOME` = a per-run or per-recording folder); role credentials are added **only** to the one `open
  --login` (or `login`) call that needs them, then dropped (D3, 51-03 S4).
- **Session defaults** (D8): `--allow-host <QA host>`, `--mode full`, `--upload-root <workspace>/tests/resources`,
  `--browser chromium` (or the setting), `--artifacts <run folder>`, `--idle-timeout 30`.
- **Subprocess hygiene (F8)**: every call has a timeout; long-lived children (daemons, recorders, Playwright runs) start
  in their own process group, their pgid is written to `<run folder>/.pids/`; on timeout, cancel or pause the client
  (and, for a killed worker, the RunManager on `run.final`/cancel plus a startup sweep that holds the run-owner lock,
  L-097) kills those groups. `apwt close-all` for the run's `PLAYWRIGHT_APPIAN_HOME` as a last resort.
- Wired for workflows as `ctx.extras['apwt']` with a `TestCredentialResolver` (§6), the `sail` pattern; the worker
  builds it, the app never imports workflow code (ADR-012).

## 4a. The sandboxed-shell agent node (D3, D3a — the 51-03 recipe)

- **`kiro-agent-sdk`** (`packages/kiro-agent-sdk/src/kiro_agent_sdk/client.py`), additive: an `env=` option on
  `KiroAgentOptions` used instead of `os.environ.copy()` when set (`client.py:182-190`); `ext_request(method, params)`
  to send an ACP extension request and await its result; a notification hook that surfaces `_kiro/sandbox/status`
  (today non-turn notifications are dropped). Tests with a fake ACP peer.
- **`genesis-core` `kiro_node`** (`packages/genesis-core/genesis_core/nodes/agent.py:195`), additive: a
  `sandboxed_shell=SandboxedShell(network_hosts=[…], read_deny=[…], write_allow=[…])` option. When set, the node:
  starts Kiro with `agent_engine="v3"`, the clean environment (S5 list) and a **per-run `KIRO_HOME`** (inside the run
  folder) holding `settings/permissions.yaml` (`fs_read` deny: `~/.ssh`, `~/.aws`, `~/.genesis`, Keychains,
  `~/.kiro`, the `apwt` saved-login `states/`; `fs_write` allow: the run folder; `sandbox_network` allow: the QA host
  only, ordered before any wildcard); after `session/new` sends `_kiro/sandbox/applyConfig` (`sandboxNetworkMode` =
  `default_blocked`, then `sandbox` = `enabled`, `mcpSandboxing` = `disabled`) and **fails the turn** unless
  `_kiro/sandbox/status` reports `active` within the startup timeout; runs `permission_mode="ask"` with a policy that
  allows only tool calls of kind `execute` (correlated by `toolCallId`) and the blackboard MCP tools, denying
  everything else (fail-closed, L-017). It never passes `--trust-all-tools` or `--trust-tools` (V3 rejects the
  latter). The ADR-029 MCP intersection still applies to any MCP server the node declares.
- Skills keep provisioning into `<cwd>/.kiro/skills/` (ADR-069) — 51-03 S11 confirms V3 with a custom `KIRO_HOME`
  still discovers them.
- Every sandboxed node's run records the `_kiro/sandbox/status` payload in its telemetry (evidence the boundary was on).

## 5. Environment types (D5, F3)

`genesis/genesis/config/environments.py`: `type` becomes an enum `dev | qa | uat | production | other` (labels Dev, QA,
UAT, Production, Other). Rules: exactly one `dev` (today's single-select `is_dev`, ADR-036/048 unchanged), **at most one
`qa`**; the QA host must differ from every other environment's host (D8.1). `dev_environment()` keeps its contract;
new `qa_environment()`. **Compatibility**: on read, an entry with `is_dev: true` is `dev`; a free-text `type` of
prod/production → `production`, any other text → `other` with the old text appended to `notes` (F3); on write, `type`
is the home and `is_dev` is written as a **mirror** for older Genesis versions reading the same file (the fleet's
`userb`); remove the mirror in a later phase. API: `POST /config/environments` accepts `type`; `POST
/config/environments/{label}/dev` stays (sets `type=dev`) for old clients (`genesis/genesis/api/config_routes.py:86`).

## 6. Test settings and test users (D5, F12)

- Service (`genesis/genesis/testexec/settings_service.py`): get/set the app's `site_path` (suggested from the KB's Site
  objects' URL stubs where the KB has them), list/add/edit/remove test users; set/clear a user's password through the
  SecretProvider (`genesis/genesis/config/secrets.py`) under scope `testusers-<sha1(app_uuid)[:16]>`, var
  `<ROLE_KEY with - → _, upper>_PASSWORD`; status shows set/unset only (values never returned). Warning when a username
  equals the Dev environment's `LCP_USERNAME` (F12).
- `TestCredentialResolver(app_uuid, role_key) → (username, password)`: used only by `ApwtClient` calls and the test
  process environment (51-06 §4); never written to state, events, files or logs (ADR-010; redaction via the existing
  logging filter `genesis/genesis/runtime/logging.py:38`).
- `readiness(app_uuid)` → a list of blocking problems (no QA env, no site path, no test user, no Node, no Chromium,
  workspace not installed), used by every start endpoint and the Setup view.

## 7. Tests

Environment migration cases (is_dev, free text, missing type); single Dev / single QA / host collision refusals;
mirror written; workspace creation in a temp HOME (git repo, files, ignore rules) with npm stubbed; write → typecheck
failure refuses commit; export at a commit; `ApwtClient` argv building, env allow-list (no secret leaks: assert the env
passed to `subprocess`), timeout kills the process group (a real sleeping child), error-code mapping from recorded
`--json` outputs (fixtures copied from real `apwt` 0.2.0 output, L-083); credential resolver never logs values.
