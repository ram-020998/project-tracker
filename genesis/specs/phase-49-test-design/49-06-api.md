# 49-06 — HTTP API

> **Status:** SPEC-DRAFTED 2026-10-26. Repo: **genesis** (backend). Parent: `specs/phase-49-test-design.md`.
> The single home of the phase's HTTP contract. Routes are thin over 49-02 (store), 49-04 (stage services) and 49-05
> (impact). Under `/api` (ADR-028); plain `def` handlers; JSON errors `{detail}`.

## 1. Module + registration

New `genesis/genesis/api/testdesign.py` → `register_testdesign_routes(api, settings, kb_store, run_manager, …)`,
registered in `genesis/genesis/api/app.py` like `register_object_wiki_routes`. The generic stage routes in
`features.py` (`GET /features/{id}/stages/{stage}`, actions, `export.md`) already serve `test_design` once it is in
`VALID_STAGES` (49-04 §2). Status codes: 404 unknown feature/record; 409 lifecycle/state conflicts (message from the
service) and CAS conflicts (`StaleWriteError`, the house rule); 422 malformed payload/artifact.

Added after the 49-05 build (49-05 As built):
- `ImpactNotFoundError` → **404**, `ImpactConflictError` → **409** (`genesis/genesis/services/testimpact.py:53-57`).
- **On-demand resolution (R8):** `GET /features/{id}/test-suite`, `GET /test-cases/{cid}` and
  `POST /applications/{app}/test-impact` call `TestImpactService.resolve_unresolved(app_uuid)` (`testimpact.py:332`,
  idempotent) before reading, so recovery is never startup-only. This also covers KB rows that arrive through a Hub
  KB pull, so no separate pull trigger is added. Run it off the event loop (the handlers are plain `def`).
- The impact result carries fields beyond the 49-05 §5 shape: `hop` on each suite, `object_removed` on each case and on
  each `via` path entry. Keep them in the response and in the contract fixture the web types mirror (L-011).
- A sync for the sync source must have `kb_syncs.status = 'succeeded'`; the syncs picker lists only those.

Added after the 49-04 build (49-04 As built):
- **Route order:** register `/features/{id}/stages/test_design/start`, `/rerun` and `/finalize` **before** the generic
  `/features/{id}/stages/{stage}/…` routes in `features.py`, or the generic ones catch them. Add a test that hits each
  specific route and proves the specific handler answered.
- **Error mapping:** `TestDesignStageService` raises errors that carry their status (404 / 409 / 422); map them
  one-to-one, keep the message as `detail`.
- **Stage status reads:** any test-design-specific status read (e.g. the suite read before Finalize, a top-up status
  read) calls `StageFinalizer.reconcile_stage(stage_id)` first. RunManager notifies observers of `run.final` before it
  stores the terminal status (`genesis/genesis/runs/manager.py:137-139`), so the live finalize can miss; the
  level-triggered read recovers it (L-058).

**Changed**

  stage_finalizer)` holds every route in §2–§6. One `_call` maps the errors: `TestDesignError` by its `.status`;
  `ImpactNotFoundError` → 404; `ImpactConflictError` → 409; `StaleWriteError` → 409 `{error: "stale_write", expected,

**Decisions / deviations** (no ADR deviation):
1. GET `/test-cases/{cid}`, GET `/test-scenarios/{sid}` and both `…/transition` responses add `allowed` (from
   `LifecycleService.allowed`), so 49-07 offers only legal actions (ADR-050). No test precondition filters it, so
   Retire, Approve and Restore stay offered and a refusal carries the reason.
2. Lifecycle refusals use the house 409 body. The web reads `detail.reason` (which names the blocking scenarios) or
   `detail.allowed`, not a string.
3. `ScenarioDto` steps carry `case_title` and `case_status`. GET `/test-scenarios/{sid}` returns `objects` derived as
   one entry per object (uuid, or name + type while unresolved): `{object_uuid, object_name, object_type, state,
   case_keys}`, where `state` is the worst across the scenario's cases (removed > suspect > unresolved > resolved).
4. `coverage.stories[].cases` / `needs_review` count non-retired cases; `coverage.needs_review` counts distinct
   non-retired cases that need review; `uncovered` counts Story-type stories with no case (Tasks are `task`, D14).
5. The story and object test-case lists include retired cases, last. The object read also runs the on-demand resolve.
6. The impact route may resolve pending object links before it computes (§1, R8). It stores no impact data and makes
   no Hub call. The read-only test checks that nothing changes once that resolve has nothing left to do. **For
   genesis-docs:** §6's "read-only (no writes, no Hub call)" should read "stores no impact data and makes no Hub call;
   it may resolve pending object links first".
7. The top-up start body is JSON (`{story_ids, notes?}`, no files), as §3 says.
8. `GET /features/{id}/test-suite/topups/latest` returns 404 for an unknown feature (§3 lists no error).
9. Manual create refusals write nothing and use no `TC-`/`TS-` key.
10. The contract fixtures live under `web/src/test/fixtures/testdesign/`, beside the existing golden fixtures.

**Hand-offs**

  fails on a shape drift). Read lifecycle 409s as `detail.reason` / `detail.allowed`, and CAS 409s as

  (`notes`, `files`); the top-up start is JSON.
- **49-08:** the live check should open a case page during a KB sync. It should not stall, because the resolve takes no
  lock when nothing is pending.
- **genesis-docs:** the §6 wording (decision 6). In the code map, `api/` gains `testdesign.py`.

**Lesson candidates**
- FastAPI ≥ 0.139 wraps an included router in one `_IncludedRouter` entry in `app.routes`. A route-order test must read
  `original_router.routes`, and must also prove by behaviour that the specific handler answered.
- A level-triggered recovery that runs on every read must check read-only first and take a write lock only when there
  is work. Otherwise every read queues behind any writer (here, up to the 30 s `busy_timeout` during a KB sync).

**Code-map changes:** `api/` gains `testdesign.py` (`register_testdesign_routes`, registered before the features
routes). `kb/testdesign.py` gains `_scenario_dtos`, `cases_for_scenario`, `feature_id_for_suite`, and create-with-links
on `create_case` / `create_scenario`. `services/testdesign_stage.py` gains `suite_view` and `suite_coverage`.
`web/src/test/fixtures/testdesign/` holds the Test Design contract fixtures.
