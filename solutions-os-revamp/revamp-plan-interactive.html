Unified MCP Architecture

One Docker image. Graceful degradation. Dynamic tool registration.

🐳 Single Docker Image

One image, configurable planes via environment variables.

VariableEnables
GITLAB_TOKENCloud Plane (30+ tools)
APPIAN_ENV_URLLive Plane (25+ tools)
APPIAN_API_KEYLive Plane auth

Graceful degradation: Only GITLAB_TOKEN? Cloud-only mode. Only APPIAN_ENV_URL? Live-only mode. Both? Full 50+ tools.

📋 One MCP Config

{ "mcpServers": { "appian": { "command": "docker", "args": ["run", "--rm", "-i", ...], "env": { "GITLAB_TOKEN": "${GITLAB_TOKEN}", "APPIAN_ENV_URL": "${APPIAN_ENV_URL}", "APPIAN_API_KEY": "${APPIAN_API_KEY}" } } } }

Replaces 3 separate configs (atlas-mcp.json, jarvis mcp.json, data-gen mcp.json).

🔌 Dynamic Tool Registration

Server only registers tools for active planes — agents see only what they can use. Adding a new tool = one PR, one deployment, all users get it.

appian_intelligence/ ├── server.py # MCP server + tool registration ├── router.py # Decides which plane handles each call ├── cloud/ # Cloud Plane (ex-Atlas) │ ├── client.py # GitLab API │ └── tools/ # application, bundle, version, graph, schema ├── live/ # Live Plane (ex-Jarvis) │ ├── client.py # Appian HTTP client │ └── tools/ # object, deployment, expression, sql, kb └── data_gen/ # Data Generator Plane ├── client.py └── tools/ # record, properties, session

Orchestrator Agent

User: "How does evaluation scoring work in GSS?" → Orchestrator classifies: codebase question, GSS app → Uses unified MCP tools directly (get_app_overview, search_objects) → Answers in 2-3 tool calls User: "Generate a design document for GAMS-7126" → Orchestrator classifies: complex workflow, needs Jira + KB + template → Delegates to developer sub-agent → Sub-agent runs full workflow, returns result

T.I.M.E. Framework

Taking Ideas to Market Expeditiously — structure that speaks to AI.

💡 Core Insight

Where a file lives tells you its maturity, its readiness, and who should pay attention. The folder structure becomes the workflow engine — moving a file triggers AI automation.

Lifecycle Stages

📚 00-context

Ground truth: vision, personas, architecture, current features

💡 01-discovery

Raw ideas, feedback, research — the intake funnel

🔬 02-refinement

Ideas shaped into feature specs and prototypes

📐 03-planning

Committed work, prioritized, ready for breakdown

🏗️ 04-delivery

Active development and quality assurance

🚀 05-shipped

The record of what made it to market

AI Actions on Transitions

→ 01-discovery

AI scans for duplicates, flags cross-suite dependencies, suggests related context

→ 02-refinement

AI expands idea using product context, generates feature card, drafts spec, kicks off prototype

→ 03-planning

AI breaks feature into tickets, estimates complexity via KB, relates to release

→ 04-delivery

AI generates design doc from spec, creates task breakdown, links to Appian objects

→ 05-shipped

AI writes release notes, updates README, archives delivery artifacts

Environment Registry

Centralized environment management — no more hardcoded URLs.

📍 Registry File

All environments in one JSON. Agents auto-select based on product context.

{ "environments": { "gam-dev2": { "url": "https://eng-test-fed-aq-dev2...", "products": ["source-selection", "vendor-mgmt"], "type": "development" }, "cms-dev": { "url": "https://eng-test-solutions-cms...", "products": ["case-management-studio"], "type": "development" } } }

🔐 Credential Separation

URLs committed to repo. Secrets stored locally (gitignored, chmod 600).

# ~/.solutions-os/credentials GAM_DEV2_API_KEY=<key> CMS_DEV_API_KEY=<key> GITLAB_TOKEN=<token>

Auto-switching: "Query evaluations in dev2" → uses GAM_DEV2. "Deploy to staging" → uses staging credentials.

Implementation Phases

6 weeks, 4 phases. Each phase has clear deliverables and exit criteria.

Phase 1: Unified MCP Server (Weeks 1-3)

Create appian-intelligence repo. Port Atlas tools into cloud/ module, Jarvis tools into live/ module, Data Gen into data_gen/. Implement router. Build Docker image. Integration tests.

Exit: docker run appian-intelligence with both env vars → all tools available via single MCP connection.

Phase 2: Orchestrator + Sub-Agents (Weeks 2-4)

Write orchestrator prompt + capabilities registry. Convert all powers to agent JSON configs. Create skills from reference material. Single MCP config at .kiro/settings/mcp.json. Setup script.

Exit: New user runs ./setup.sh && kiro-cli --agent solutions-os → can explore apps, ask questions, delegate.

Phase 3: Repo Restructure (Weeks 4-5)

Move prompts, create orchestrator directory, remove old powers, fix product folder inconsistencies, add T.I.M.E. lifecycle folders, CI validation checks, update README.

Exit: Repo structure matches new layout. CI passes. No references to old power paths.

Phase 4: Migration & Deprecation (Weeks 5-6)

Write migration guide. Add deprecation notices. Run workshop. Verify all SWAT projects work. Clean up old Docker images.

Exit: Zero users on old power-based workflow. All teams using orchestrator.
