## COMMON FAILURES TO AVOID

| Failure | Why It's Bad | How to Prevent |
|---------|-------------|----------------|
| Hardcoding reference data values | Different env = different IDs = broken data | Query LIVE with data-generator.query_records |
| Inventing usernames | Invalid user = write failure | Always use data-generator.list_users() values |
| Skipping field mapping for "simple" tables | Missing fields in payloads = incomplete data | Map EVERY included table |
| Not checking isCustomRecordField | Writing to computed fields = API error | Call data-generator.get_record_properties if unsure |
| Wrong insertion order | FK violation = create failure | Follow solutions-intelligence.get_insertion_order strictly |
| Leaving tables as "TBD" | Ambiguity in Step 4 = guessed payloads | Decide NOW — INCLUDE or EXCLUDE |
